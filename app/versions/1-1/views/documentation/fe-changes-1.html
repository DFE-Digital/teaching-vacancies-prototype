2. How the maps connect

Hiring staff choose the application method at HS16. That choice locks the jobseeker onto a Quick Apply (KCSIE) form journey, a religious-form variant, or an external / upload route. FE Quick Apply is not fully built yet; this doc records where FE content and design must catch up on the jobseeker side.

3. Prototype reality (v1.1 today)

  • Live Quick Apply is one shared journey: /jobs/:id/apply/* via routes/application-flow.js and views/apply/flow/. There is no college branching — college vacancies still get QTS / TRN / ECT screens.
  • FE-leaning stub (separate): /apply/professional-status → /apply/maths-and-english in routes/jobs.js. Tail is broken: redirects to /apply/references_nochildren with no GET route.
  • Religion / RC / RQ screens exist as orphan views/apply/religion_*.njk templates — not mounted on the live apply router (equal-ops religion field only).
  • Existing documentation hub only describes the FE stub, not full Quick Apply FE parity.
